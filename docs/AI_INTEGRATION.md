# 实际接入说明与改动清单

## 数据和调用链

`FishUI`持有`AiController`和AI模式按钮；`ActListener`处理H键与人工接管；`GameLoop`每20毫秒的Swing定时器回调先移动其他鱼，再由控制器构造不可变Body快照，调用`AiAdvisor`，将最终方向写入玩家的方向标志，然后调用原`Fish.move`和碰撞检查，更新界面。

这是实际游戏调用链。`AdvisorCli`只供自动化测试使用；游戏不启动Python或子进程。所有游戏快照读取、动作执行、碰撞及界面更新都在Swing EDT串行进行，避免旧线程同时遍历/修改鱼列表。当前模型仅1600条，采用单遍选3个最近邻，不在每帧排序整个样本库。没有对所有设备进行帧率保证。

Python训练模型1600条样本以原顺序无损导出到TSV。3NN的特征、距离、投票和同分顺序与Python一致。训练数据为合成规则专家数据，不是假称来自真实玩家的记录。它是本地监督学习分类器，不是LLM。

## 接入时消除的契约差异

- Java安全过滤采用原`Fish.move`的严格边界：向左后x必须大于0，向右后x+width必须小于1900，纵向同理。Python参考实现允许恰好贴边；因此边界最终动作不应强求跨实现逐字相等。
- Java从`Fish.getY_speed()`读取纵向速度，支持道具状态下速度变化；不再假定横向/纵向速度必定相等。
- 只有state=1的玩家能被AI控制；模型不改变score、排行榜或游戏胜负判定。
- AI关闭/建议/托管切换会清除旧方向；手动WASD退出托管；暂停清除运动标志并停止三个定时器。
- 结构化模型只接收业务数值，不接收姓名、性别或皮肤。对应公平性测试验证测试适配器及决策的数据隔离，不等于真实人群结果平等。

## 原模块一代码的配套修复

1. 排行榜仅把0:0作为空位，保留1:00等整分钟成绩。
2. 插入榜单采用局部候选变量，不覆盖本局m/s。
3. ImagePool非法下标安全返回null；图片改为classpath加载、共享缓存，避免每条鱼重复读取全部图片。
4. 秒数setter归一化进位；游戏计时调用该setter，避免10:60。
5. 原Thread.stop/suspend/resume游戏循环替换为Swing Timer，兼容本机JDK21，并统一状态更新线程。
6. 删除启动时对隐藏面板getGraphics()的直接绘制，main改为EDT启动；补齐原压缩包缺少的三个空存档文件。
7. Maven的JDK要求改为8及以上，并纳入新增Java集成测试；离线测试入口不依赖Maven。

原36条测试保持不变，实际全通过。整分钟有效、setter负责归一化是本集成版本明确采用的业务契约，和旧缺陷清单里的“待确认”有所不同，报告应说明版本变化。代码未覆盖所有原游戏潜在问题，不承诺完整游戏无缺陷。

## 测AI证据及限制

400个独立留出样本的原始分类准确率为93.25%，仍有27个方向误分类；30个方法满足设定阈值不代表每次预测正确。90对身份对照差异率为0。随机种子和样本输入都在测试源码/JSON结果中。

AI-DEF-001：玩家在左边界而强鱼在右侧，模型仍输出LEFT；raw测试能真实失败，guarded会换为合法动作。原因是模型特征没有绝对位置，防护层补足动作可执行性。完整缺陷分析见`ai-tests/docs/DEFECT.md`（其中Python基线报告路径为上一次独立实现的参考记录）；当前集成结果以java-guarded和java-raw目录为准。

防护目前只看静态快照的一步终点、保守矩形碰撞，不预测敌鱼未来运动，不检查整条移动路径，不保证长期存活。无安全候选时返回STAY和no_safe_action，表示无法给出安全动作，不表示已经安全。没有完整人工试玩、跨设备测试或实际游戏通关率数据。
